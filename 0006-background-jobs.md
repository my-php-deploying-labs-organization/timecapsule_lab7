# ADR-0006: Выполнение фоновых задач приложения

## Статус

Принято.

## Контекст

В ЛР6 отправка уведомлений задерживала HTTP-запрос на MAIL_DELAY_SECONDS (3 с). Открытие капсул выполнялось при обращениях к сайту; при отсутствии запросов оно откладывалось, а несколько EC2 выполняли одинаковые проверки.

## Варианты

| Критерий | Веб-запрос | Cron на EC2 | Lambda + SNS + SQS |
|---|---|---|---|
| Задержка HTTP | Включает отправку | Фоновая работа при отдельной очереди | Только публикация |
| Открытие без посещений | Нет | Да | Да |
| Координация ASG | Повторные проверки | Нужна блокировка/выделенный worker | Атомарный SQL и управляемое расписание |
| Повторы и хранение ошибок | Реализовать самостоятельно | Реализовать самостоятельно | SQS и DLQ |
| Обслуживание | EC2 | EC2 и cron | Управляемые функции |

## Решение

Использовать SNS Standard, SQS Standard с DLQ, Lambda Mailer и Opener, EventBridge Scheduler. Mailer работает с RDS через приватные подсети, получает сообщения через event source mapping. Opener открывает капсулы атомарным UPDATE ... RETURNING; результат передаётся в SNS через On success Destination. Email подписан с фильтром тела сообщения. EC2 публикует через IAM instance role, без ключей в коде.

## Последствия

- HTTP-запрос не ждёт имитации отправки; уведомление появляется асинхронно.
- При сбое Mailer сообщения повторно доставляются, после пяти получений перемещаются в DLQ; после восстановления возможен redrive. Сроки хранения ограничены 4 и 14 днями соответственно.
- При остановке RDS Mailer не может записать уведомление, Opener не может открыть капсулы. После запуска базы следующий успешный Opener обработает просроченные капсулы; сообщения DLQ возвращаются вручную.
- UNIQUE INDEX по event_id и INSERT ... ON CONFLICT DO NOTHING обеспечивают идемпотентность уведомлений даже при параллельной доставке. UPDATE с opened_at IS NULL предотвращает повторное открытие.
- Ограничение параллельности Mailer равно 2 на уровне SQS mapping; Reserved concurrency не используется из-за квоты аккаунта.
- Открытие по расписанию может задерживаться примерно на интервал запуска или дольше при сбоях.
- Публикация после коммита не атомарна: возможна потеря события при ошибке SNS или Destination. Для более строгих гарантий необходим Transactional Outbox и механизм повторной публикации.
- Пустые результаты Opener поступают в SQS; это лишние вызовы и подключения. Большой список открытых капсул может превысить таймаут Mailer при последовательной обработке.

## Параметры

Visibility timeout 180 с (6 × Lambda timeout 30 с), batch size 1, maxReceiveCount 5, maximum concurrency 2, память 128 МБ, интервал расписания 1 минута.
